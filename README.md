# dsh-path-guard

在 DSH 开启 **完全权限（`danger-full-access`）** 时，仍然按路径阻止 AI 读取/写入。

- **档位一 · 完全无访问**：连目录结构、文件名都拿不到。
- **档位二 · 半访问控制**：可见文件名与目录结构但不可读内容，或可读不可写（三档能力独立可配）。
- **豁免规则**：更具体的路径覆盖更宽泛的规则，例如 `.ssh/**` 半访问，但 `.ssh/README.md` 豁免为可读。
- **配置面**：DSH 0.1.7-rc2 的前端插件配置页，无需手改 YAML。
- **实现原则**：**不接管任何现有服务、不覆盖任何上游 row**，只通过 `tools/pre-execute`、`ctx.tools.guard()`、`fs/*-intent`、`tools/post-execute` 四个既有扩展点做增量拦截。

设计与实施计划见 [`docs/PLAN.md`](docs/PLAN.md)；研究证据留档在 [`reports/`](reports/)。

> 状态：**规划阶段（计划第 2 版，待评审）**。仓库当前只包含文档，尚未实现代码。

## 关键限制（先说清楚）

`bash` / `pwsh` / `run_code` / 跨进程子代理 / MCP 服务是真实进程或外部工具循环，**插件层无法可靠围栏**；本插件对它们提供「按名拒绝」或「命令文本尽力扫描」，默认配置为**直接拒绝**。此外，DSH 的 ACL 沙箱当前无法表达「按路径拒绝」，因此不存在内核级方案。

细节、可证伪点与完整残余风险清单见 `docs/PLAN.md` §2.2 与 §9。
